## Objective

Replace the application's artwork with the new set in `C:\Dev\EnigmaLibs\Branding\Apps\final2\msi`
(`enigma-msi.ico`, `enigma-msi.svg`, `png/enigma-msi-{16,20,24,32,40,48,64,96,128,256}.png`). Update
every place the repository carries it: the executable and window icon, the `app.ico` copied beside the
executable, the About dialog's image, and the Linux installer's icons.

## Context & constraints

- **The new artwork** is the same drawing as `FEATURE-25EF`'s: a taped cube in the *Soft* palette (blue
  `#6A9BF4` / `#4F7FDB` / `#D9E5FC`, green tape `#63C77D`). It no longer has the dark rounded tile, so the
  background is transparent. The SVG's header names it "MSI-A2 … Taped cube", generated by
  `Branding/Apps/export.py final2`.
- **The new `.ico`** has the same ten 32-bit RGBA PNG frames as today's (16, 20, 24, 32, 40, 48, 64, 96,
  128, 256). Each frame is byte for byte the matching `png/enigma-msi-N.png` (checked while planning).
- **Where the artwork lives** (unchanged since `FEATURE-25EF` and `FEATURE-C7BF`; the file names were kept
  on purpose):
  - `src/Enigma.Msi.Desktop/Assets/appicon.ico` is the `ApplicationIcon`, the main window's `Icon` and
    the `app.ico` written beside the executable. It is also an `AvaloniaResource`.
  - `src/Enigma.Msi.Desktop/Assets/logo.png` is the About card's image, the `.ico`'s 256 px frame.
  - `packaging/linux/icons/enigma-msi-{16,24,32,48,64,96,128,256}.png` are what `install.sh` installs
    (`ICON_SIZES`, eight sizes: no 20 or 40).
- `AppIconTests` (Desktop suite) checks that `app.ico` is beside the test assembly and identical to the
  embedded `appicon.ico`. It stays valid unchanged.
- The SVG master is not carried by this repository: CLAUDE.md records that it lives in `Branding/Apps`.
- The source directory is outside the repository and is left in place.

## Steps

1. Copy, byte for byte:
   - `enigma-msi.ico` → `src/Enigma.Msi.Desktop/Assets/appicon.ico`;
   - `png/enigma-msi-256.png` → `src/Enigma.Msi.Desktop/Assets/logo.png`;
   - `png/enigma-msi-{16,24,32,48,64,96,128,256}.png` → `packaging/linux/icons/`.
2. Check that no prose or comment describes the icon's dark tile (README, guides, XAML comments). Fix
   any that does.
3. Release build and the whole suite. A script check confirms the frame layout.

## Acceptance criteria

- The three destinations hold the new files byte for byte (`cmp`). No old artwork is left.
- A script check shows ten 32-bit RGBA PNG frames (16 to 256) in `appicon.ico`. `logo.png` is its 256
  frame byte for byte, and each Linux PNG is the `.ico` frame of its size byte for byte.
- The Release build has zero warnings, and the whole suite shows no new failure against the run's
  baseline (`AppIconTests` included).

## Out of scope

- The application's accent colours and any UI change.
- Committing the SVG master (it stays in `Branding/Apps`).
- Release notes and the version (`FEATURE-5897`).
- Changing which sizes the Linux installer installs.
